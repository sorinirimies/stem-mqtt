# Dart

Bindings generated by [`uniffi-dart`](https://github.com/acterglobal/uniffi-dart), shipped as the pub.dev package
`stem_mqtt`. Everything is `Future`-based and **pull-style**: Dart cannot receive Rust callbacks (see
below). Read the [shared concepts](README.md) first for the option records and semantics.

## Install

```sh
dart pub add stem_mqtt
```

```dart
import 'package:stem_mqtt/mqtt_broker.dart' as broker_api;
import 'package:stem_mqtt/mqtt_client.dart';
```

Import the broker with a prefix: both libraries define a `QoS`, and the client's is the one you will use
most.

## Requirements

- Dart 3.9+ (native assets / build hooks).
- **A Rust toolchain (`cargo`)**. The package ships the Rust sources and a build hook
  (`hook/build.dart`) that compiles them for the machine running Dart the first time you `dart run`
  / `dart test` / `dart compile exe`. Subsequent runs reuse the build.
- Desktop and server Dart (VM, AOT) on Linux, macOS and Windows. Cross-compiling for Flutter mobile
  targets is not supported yet.

## Quick start

```dart
import 'dart:convert';
import 'dart:typed_data';

import 'package:stem_mqtt/mqtt_broker.dart' as broker_api;
import 'package:stem_mqtt/mqtt_client.dart';

ConnectOptions options(int port, String id) => ConnectOptions(
      host: '127.0.0.1', port: port, clientId: id, version: MqttVersion.v5,
      cleanStart: true, keepAliveSecs: 30, connectTimeoutSecs: 10, operationTimeoutSecs: 5,
      autoReconnect: false, reconnectBackoffSecs: 0, reconnectMaxBackoffSecs: 0,
    );

Future<void> main() async {
  final broker = broker_api.MqttBroker(
      config: broker_api.MqttBrokerConfig(
    bindAddress: '127.0.0.1', port: 0, allowAnonymous: true, maxClients: 0,
    maxQos: broker_api.QoS.exactlyOnce, maxRetainedMessages: 100, maxQueuedPerClient: 100,
    redeliveryIntervalSecs: 0,
  ));
  await broker.start();
  final port = broker.boundPort()!;

  final sub = MqttClient(options: options(port, 'dart-sub'));
  sub.enableMessageQueue(capacity: 16);            // pull, don't push
  await sub.connect();
  await sub.subscribe(topicFilter: 'demo/#', qos: QoS.atLeastOnce);

  final pub = MqttClient(options: options(port, 'dart-pub'));
  await pub.connect();
  await pub.publish(
      topic: 'demo/hello',
      payload: Uint8List.fromList(utf8.encode('hello')),
      qos: QoS.atLeastOnce,
      retain: false);

  final message = await sub.nextMessage(timeoutMs: 5000);   // null on timeout
  print('${message!.topic}: ${utf8.decode(message.payload)}');

  await pub.disconnect();
  await sub.disconnect();
  await broker.stop();
}
```

`tls`, `will`, `username`, `password`, `maxPacketSize`, `authMethod`, `authData` (client) and `wsPort`, `tls`,
`maxPacketSize`, `maxOutboundQueue`, `sessionExpirySecs` (broker) are optional named parameters.

## Why pull-style

Rust invokes callbacks from its own threads, and the Dart VM aborts with *"Cannot invoke native callback
outside an isolate"*. So `MqttMessageListener`, `MqttAuthProvider`, `MqttBrokerEventListener` and the
enhanced-auth callbacks **cannot be implemented in Dart**; use the pull API instead:

| Instead of | Use |
| --- | --- |
| `setMessageListener` | `client.enableMessageQueue(capacity: n)` + `await client.nextMessage(timeoutMs: ms)` |
| `setEventListener` | `broker.enableEventQueue(capacity: n)` + `await broker.nextEvent(timeoutMs: ms)` |
| `setAuthProvider` | `allowAnonymous: false` (rejects credential-less clients) |

## Client

- `await connect()` (returns `ConnectResult` with `sessionPresent` and `reasonCode`), `subscribe`,
  `unsubscribe`, `publish`, `disconnect`, `nextMessage`. `isConnected()` and `enableMessageQueue` are
  synchronous. Arguments are **named**: `subscribe(topicFilter: …, qos: …)`.
- camelCase names, `Uint8List` payloads, enums as `QoS.atLeastOnce` / `MqttVersion.v5`.
- Drain a queue in a loop until it returns `null`:

```dart
for (var m = await sub.nextMessage(timeoutMs: 300); m != null; m = await sub.nextMessage(timeoutMs: 300)) {
  print(m.topic);
}
```

## Broker

`await start()` / `await stop()`, `isRunning()`, `boundPort(): int?`, `boundWsPort()`, `boundTlsPort()`,
`clientCount()`. Events come from the queue:

```dart
broker.enableEventQueue(capacity: 64);                      // before start()
final event = await broker.nextEvent(timeoutMs: 1000);
if (event is broker_api.ClientConnectedBrokerEvent) print('+ ${event.clientId}');
if (event is broker_api.ClientDisconnectedBrokerEvent) print('- ${event.clientId} (${event.reason})');
if (event is broker_api.MessagePublishedBrokerEvent) print('${event.clientId} -> ${event.topic}');
```

## TLS

```dart
final tls = TlsOptions(
  caCertPem: File('ca.pem').readAsBytesSync(),
  insecureSkipCertificateVerification: false,
);
// ConnectOptions(…, tls: tls)

final brokerTls = broker_api.BrokerTlsConfig(
  port: 8883,
  certPem: File('server.pem').readAsBytesSync(),
  keyPem: File('server.key').readAsBytesSync(),
);
// MqttBrokerConfig(…, tls: brokerTls)
```

## Language notes

- Errors: `MqttException` and `broker_api.MqttBrokerException` are **enums** (`connectionRefused`,
  `timeout`, `protocol`, …) thrown from the `Future`; the detail message is not carried.
  `catch (_)` is enough to detect a refused login.
- Call `exit(0)` at the end of a `main` that started a broker if the process does not terminate on its
  own (native handles keep the VM alive).
- The generated code addresses its native asset as `package:stem_mqtt/uniffi:mqtt_broker`; the client
  and broker components live in the same library.

## Troubleshooting

- **`StateError: cargo build failed - is a Rust toolchain installed`** — install Rust (<https://rustup.rs>).
- **`Cannot invoke native callback outside an isolate`** — you registered a listener/provider; use the pull API.
- **`UnsupportedError: stem_mqtt builds its Rust core on the host only`** — you are compiling for a
  different target OS than the machine; cross-compilation isn't supported.
- **A slow first run** — that is the Rust build; it is cached afterwards.
