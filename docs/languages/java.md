# Java

Bindings generated by [`uniffi-bindgen-java`](https://github.com/IronCoreLabs/uniffi-bindgen-java) using the
**Foreign Function & Memory API** (no JNA, no JNI). Asynchronous calls return `CompletableFuture`.
Read the [shared concepts](README.md) first for the option records and semantics.

## Install

```kotlin
// Gradle
implementation("io.github.sorinirimies.stemmqtt:stem-mqtt-java:<version>")      // Maven Central
```

```xml
<!-- Maven -->
<dependency>
  <groupId>io.github.sorinirimies.stemmqtt</groupId>
  <artifactId>stem-mqtt-java</artifactId>
  <version>VERSION</version>
</dependency>
```

GitHub Packages and Gitea's Maven registry publish the same artifact under the group
`com.github.sorinirimies.stemmqtt` (they need a token to read).

## Requirements

- **JDK 22 or newer** (the Foreign Function & Memory API is final in 22). The bindings are compiled
  with `--release 22`.
- Run with `--enable-native-access=ALL-UNNAMED` (or name your module) — without it the JVM warns or,
  on newer JDKs, refuses native access.
- The jar bundles the native libraries for its publishing host (Linux x86_64 today). They are extracted
  to a temp directory on first use (`io.github.stemmqtt.NativeLoader`), so no `java.library.path` is
  needed. For your own build, set `-Djava.library.path=<dir>` or
  `-Duniffi.component.mqtt_client.libraryOverride=/path/libmqtt_client.so` (same for `mqtt_broker`).

## Quick start

```java
import java.nio.charset.StandardCharsets;
import java.util.concurrent.*;
import uniffi.mqtt_broker.*;
import uniffi.mqtt_client.*;

public class Demo {
    static ConnectOptions options(short port, String id) {
        return new ConnectOptions("127.0.0.1", port, id, MqttVersion.V5, true, (short) 30, null, null, null,
                10, 5, false, 0, 0, null, 0, null, null);
    }

    public static void main(String[] args) throws Exception {
        // MqttBrokerConfig: bind, port, wsPort, allowAnonymous, maxClients, maxQos, maxRetained,
        // maxQueued, redeliverySecs, tls, maxPacketSize, maxOutboundQueue, sessionExpirySecs
        MqttBroker broker = new MqttBroker(new MqttBrokerConfig("127.0.0.1", (short) 0, null, true, 0,
                uniffi.mqtt_broker.QoS.EXACTLY_ONCE, 100, 100, 0, null, 0, 0, 0));
        broker.start().get(10, TimeUnit.SECONDS);
        short port = broker.boundPort();

        BlockingQueue<MqttMessage> inbox = new LinkedBlockingQueue<>();
        MqttClient sub = new MqttClient(options(port, "java-sub"));
        sub.setMessageListener(new MqttMessageListener() {
            public void onMessage(MqttMessage message) { inbox.add(message); }
            public void onDisconnected(String reason) { }
        });
        sub.connect().get(10, TimeUnit.SECONDS);
        sub.subscribe("demo/#", uniffi.mqtt_client.QoS.AT_LEAST_ONCE).get(10, TimeUnit.SECONDS);

        MqttClient pub = new MqttClient(options(port, "java-pub"));
        pub.connect().get(10, TimeUnit.SECONDS);
        pub.publish("demo/hello", "hello".getBytes(StandardCharsets.UTF_8),
                uniffi.mqtt_client.QoS.AT_LEAST_ONCE, false).get(10, TimeUnit.SECONDS);

        MqttMessage message = inbox.poll(5, TimeUnit.SECONDS);
        System.out.println(message.topic() + ": " + new String(message.payload(), StandardCharsets.UTF_8));

        pub.disconnect().get(); sub.disconnect().get(); broker.stop().get();
        System.exit(0);   // the FFM cleaner threads are non-daemon on some JDKs
    }
}
```

```sh
javac --release 22 -cp stem-mqtt-java.jar Demo.java
java --enable-native-access=ALL-UNNAMED -cp stem-mqtt-java.jar:. Demo
```

## Client

- `connect()`, `subscribe(filter, qos)`, `unsubscribe(filter)`, `publish(topic, byte[], qos, retain)`,
  `disconnect()`, `nextMessage(timeoutMs)` return `CompletableFuture`s (each has an overload taking an
  `Executor`; the default is the common pool). `isConnected()`, `setMessageListener()`,
  `enableMessageQueue(capacity)`, `lastDisconnectReason()` are synchronous.
- Records are classes with **constructors that take every field positionally** (Java has no default
  arguments) and accessor methods named after the fields: `result.reasonCode()`, `message.topic()`,
  `message.payload()`. `ConnectOptions` order: host, port, clientId, version, cleanStart, keepAliveSecs,
  username, password, will, connectTimeoutSecs, operationTimeoutSecs, autoReconnect,
  reconnectBackoffSecs, reconnectMaxBackoffSecs, tls, maxPacketSize, authMethod, authData.
- Ports and `keepAliveSecs` are `short` — cast literals: `(short) 1883`, `(short) 30`.
- Enums are `UPPER_SNAKE`: `QoS.AT_LEAST_ONCE`, `MqttVersion.V5`. Optional values are `null`.
- **Callbacks** are plain interfaces (`MqttMessageListener`, …), so lambdas work for the single-method
  ones (`broker.setAuthProvider((clientId, username, password) -> …)`). They run on a native thread.
- **Or pull**: `enableMessageQueue(16)`, then `client.nextMessage(5000).get()` → message or `null`.

## Broker

`start()` / `stop()` return `CompletableFuture<Void>`; `isRunning()`, `boundPort()` (`Short`, `null`
before start), `boundWsPort()`, `boundTlsPort()`, `clientCount()`. The config constructor order is in the
comment above. `MqttBroker` and `MqttClient` implement `AutoCloseable`.

```java
broker.setEventListener(new MqttBrokerEventListener() {
    public void onClientConnected(String clientId) { System.out.println("+ " + clientId); }
    public void onClientDisconnected(String clientId, String reason) { }
    public void onMessagePublished(String clientId, String topic, uniffi.mqtt_broker.QoS qos) { }
});
```

## Authentication

```java
broker.setAuthProvider((clientId, username, password) -> "demo".equals(username));
```

A refused client makes the `connect()` future complete exceptionally with an `ExecutionException`
wrapping `uniffi.mqtt_client.MqttException.ConnectionRefused`. Enhanced authentication: implement
`MqttEnhancedAuthProvider.step(clientId, method, data, round)` returning
`new EnhancedAuthStep(EnhancedAuthOutcome.CONTINUE, bytes)` (broker) and
`MqttAuthHandler.respond(method, challenge)` (client, with `authMethod`/`authData` set).

## TLS

```java
byte[] ca = java.nio.file.Files.readAllBytes(java.nio.file.Path.of("ca.pem"));
TlsOptions tls = new TlsOptions(ca, null, null, false);      // caCertPem, clientCertPem, clientKeyPem, insecureSkip…
// pass `tls` as the 15th ConnectOptions argument

BrokerTlsConfig brokerTls = new BrokerTlsConfig((short) 8883, certPem, keyPem, null);
// pass as the `tls` argument of MqttBrokerConfig
```

## Language notes

- Exceptions: `uniffi.mqtt_client.MqttException` (static nested `ConnectionRefused`, `Timeout`,
  `Protocol`, …, a checked exception) and `uniffi.mqtt_broker.MqttBrokerException`. Futures wrap them in
  `ExecutionException`; unwrap with `getCause()`.
- The two components both have a `QoS`; **qualify one** (`uniffi.mqtt_broker.QoS`) or import only the
  package you need.
- Always call `System.exit` (or close every handle) at the end of `main`: the native cleaner threads
  keep some JDKs alive.

## Troubleshooting

- **`UnsupportedClassVersionError` / `release version 22 not supported`** — you need JDK 22+.
- **`UnsatisfiedLinkError: no mqtt_client in java.library.path`** — the jar has no native library for
  your OS/arch (see Requirements); point `java.library.path` at your own build.
- **"native access" warnings** — pass `--enable-native-access=ALL-UNNAMED`.
- **`incompatible types: int cannot be converted to short`** — cast ports and keep-alive: `(short) 1883`.
- **The JVM doesn't exit** — call `System.exit(0)` as above.
