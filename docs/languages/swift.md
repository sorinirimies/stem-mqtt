# Swift

`async`/`await` bindings generated by UniFFI's built-in Swift backend, delivered as prebuilt XCFrameworks in one
Swift package archive. Two modules, `MqttClient` and `MqttBroker`. Read the [shared concepts](README.md) first
for the option records and semantics.

## Install

Download `StemMqttSwift-<version>.zip` from the matching
[GitHub release](https://github.com/sorinirimies/stem-mqtt/releases), extract it, and add the extracted
`StemMqttSwift` directory as a **local Swift package**:

- Xcode: *File ▸ Add Package Dependencies… ▸ Add Local…* and pick the directory.
- SwiftPM: `.package(path: "../StemMqttSwift")`, then depend on the products you need:

```swift
// Package.swift
dependencies: [.package(path: "../StemMqttSwift")],
targets: [
    .executableTarget(name: "app", dependencies: [
        .product(name: "MqttClient", package: "StemMqttSwift"),
        .product(name: "MqttBroker", package: "StemMqttSwift"),
    ]),
]
```

```swift
import MqttClient
import MqttBroker
import enum MqttBroker.QoS     // see "Language notes": both modules define a QoS
```

A remote `.package(url:from:)` isn't offered on purpose: SwiftPM reads `Package.swift` from the git tag, while the
checksum of a release asset only exists after that tag's CI run, so the release ships a verified self-contained
archive instead.

## Requirements

- Swift 5.9+ / Xcode 15+.
- macOS 11+, iOS 13+ (device and simulator). The XCFrameworks contain arm64 + x86_64 slices for macOS, arm64 for
  iOS devices and arm64 + x86_64 for the iOS simulator. No Linux or Windows build.
- The zip is built on macOS in the GitHub release workflow (it needs Xcode); it is not produced by the Gitea
  pipeline.

## Quick start

```swift
import Foundation
import MqttBroker
import MqttClient
import enum MqttBroker.QoS

final class Inbox: MqttMessageListener, @unchecked Sendable {
    private let lock = NSLock()
    private var messages: [MqttMessage] = []
    func onMessage(message: MqttMessage) { lock.lock(); messages.append(message); lock.unlock() }
    func onDisconnected(reason: String) {}
    func first() -> MqttMessage? { lock.lock(); defer { lock.unlock() }; return messages.first }
}

func options(_ port: UInt16, _ id: String) -> ConnectOptions {
    ConnectOptions(
        host: "127.0.0.1", port: port, clientId: id, version: .v5, cleanStart: true,
        keepAliveSecs: 30, username: nil, password: nil, will: nil, connectTimeoutSecs: 10,
        operationTimeoutSecs: 5, autoReconnect: false, reconnectBackoffSecs: 0,
        reconnectMaxBackoffSecs: 0, tls: nil)
}

let broker = MqttBroker(config: MqttBrokerConfig(
    bindAddress: "127.0.0.1", port: 0, wsPort: nil, allowAnonymous: true, maxClients: 0,
    maxQos: .exactlyOnce, maxRetainedMessages: 100, maxQueuedPerClient: 100,
    redeliveryIntervalSecs: 0, tls: nil))
try await broker.start()
let port = broker.boundPort() ?? 0

let inbox = Inbox()
let sub = MqttClient(options: options(port, "swift-sub"))
sub.setMessageListener(listener: inbox)
_ = try await sub.connect()
_ = try await sub.subscribe(topicFilter: "demo/#", qos: .atLeastOnce)

let pub = MqttClient(options: options(port, "swift-pub"))
_ = try await pub.connect()
try await pub.publish(topic: "demo/hello", payload: Data("hello".utf8), qos: .atLeastOnce, retain: false)

for _ in 0..<50 where inbox.first() == nil { try await Task.sleep(nanoseconds: 100_000_000) }
if let m = inbox.first() { print(m.topic, String(decoding: m.payload, as: UTF8.self)) }

try await pub.disconnect()
try await sub.disconnect()
try await broker.stop()
```

`maxPacketSize`, `maxOutboundQueue`, `sessionExpirySecs`, `authMethod` and `authData` have defaults and can be
omitted.

## Client

- `try await connect()`, `subscribe(topicFilter:qos:)`, `unsubscribe(topicFilter:)`,
  `publish(topic:payload:qos:retain:)`, `disconnect()` are `async throws`. `isConnected()`,
  `setMessageListener(listener:)`, `enableMessageQueue(capacity:)`, `lastDisconnectReason()` are synchronous.
  Arguments are labelled.
- camelCase everywhere; `Data` payloads; enums are lower-camel cases (`.atLeastOnce`, `.v5`); optionals are `?`.
- **Callbacks** are protocols (`MqttMessageListener`, `MqttAuthHandler`, …). The library calls them from a
  background thread, so make the conforming type `Sendable` (`@unchecked Sendable` with a lock, as above) and
  hop to your actor (`Task { @MainActor in … }`) before touching UI.
- **Or pull**: `client.enableMessageQueue(capacity: 8)`, then `await client.nextMessage(timeoutMs: 5000)` →
  `MqttMessage?` (not `throws`).

## Broker

`try await start()` / `stop()`, `isRunning()`, `boundPort() -> UInt16?`, `boundWsPort()`, `boundTlsPort()`,
`clientCount()`. Run a broker in an app only where that makes sense (a sandboxed iOS app can't listen
in the background).

```swift
final class Events: MqttBrokerEventListener, @unchecked Sendable {
    func onClientConnected(clientId: String) { print("+", clientId) }
    func onClientDisconnected(clientId: String, reason: String) { print("-", clientId, reason) }
    func onMessagePublished(clientId: String, topic: String, qos: QoS) {}   // MqttBroker.QoS
}
broker.setEventListener(listener: Events())
```

Pull-style: `broker.enableEventQueue(capacity: 64)`, `await broker.nextEvent(timeoutMs: 1000)` → `BrokerEvent?`.

## Authentication

```swift
final class Auth: MqttAuthProvider, @unchecked Sendable {
    func authenticate(clientId: String, username: String?, password: Data?) -> Bool { username == "demo" }
}
broker.setAuthProvider(provider: Auth())
```

A refused client makes `try await client.connect()` throw (`MqttError.ConnectionRefused`). Enhanced
authentication: conform to `MqttEnhancedAuthProvider` (`step(clientId:method:data:round:) -> EnhancedAuthStep`)
on the broker and `MqttAuthHandler` (`respond(method:challenge:) -> Data`) on the client, with `authMethod` /
`authData` set.

## Language notes

- Both modules define a `QoS`; `import enum MqttBroker.QoS` makes the broker's the unqualified name for listener
  signatures (as in the quick start), while the client's `QoS` is inferred from context (`qos: .atLeastOnce`).
- Errors are Swift `Error`s (`MqttError`, `MqttBrokerError`) with a case per variant.
- The two components can't share one Swift module (UniFFI emits crate-local helper names that would collide),
  which is why they are separate products.
- Top-level `await` needs a `main.swift` (or wrap the code in `@main struct App { static func main() async throws { … } }`).

## Building from source

Needs macOS, Xcode command-line tools and the Apple Rust targets:

```sh
./packaging/swift/build_xcframework.sh 0.4.0
# → packaging/swift/dist/StemMqttSwift-0.4.0.zip
```

The script builds both crates for every Apple target, generates the Swift wrappers, assembles both XCFrameworks and
runs `swift build` against the result. Details: [`packaging/swift/README.md`](../../packaging/swift/README.md). The
end-to-end test is [`tests/bindings/swift/main.swift`](../../tests/bindings/swift/main.swift).

## Troubleshooting

- **`ambiguous use of 'QoS'`** — add `import enum MqttBroker.QoS` (or qualify the type).
- **`Cannot find 'MqttClient' in scope`** — the `MqttClient` product isn't a dependency of your target.
- **`Sendable` warnings/errors from callbacks** — mark the conforming class `@unchecked Sendable` and guard its
  state with a lock, or make it an `actor`-isolated wrapper.
- **Messages never arrive** — callbacks are asynchronous: give the program time (`Task.sleep`, as in the quick
  start) before exiting, or use the pull API.
